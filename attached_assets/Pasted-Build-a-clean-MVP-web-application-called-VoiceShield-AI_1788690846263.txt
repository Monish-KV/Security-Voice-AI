Build a clean MVP web application called “VoiceShield AI” from scratch.

IMPORTANT: This is a real ML voice-deepfake detection prototype. Do NOT replace the ML pipeline with heuristics, keyword matching, random scores, hashes, filename detection, or synthetic/demo predictions.

TECH STACK
- Python
- Flask
- TensorFlow/Keras
- Librosa
- NumPy
- SciPy
- SoundFile
- HTML/CSS/vanilla JavaScript
- Keep the architecture simple and easy to debug.

CORE PURPOSE
The application must accept a user's real voice recording and run the actual trained Keras models:
- models/audio_deepfake_v2.keras
- models/audio_deepfake_v4.keras

If these model files are not present, clearly report that they are missing. Do NOT create substitute models.

AUDIO PIPELINE
1. User uploads WAV, MP3, M4A, or other commonly supported audio.
2. Decode/convert the audio as necessary.
3. Convert to 16 kHz mono.
4. Validate that usable speech/audio exists.
5. Use the same general preprocessing expected by the existing V2/V4 models:
   - 16 kHz audio
   - 3-second windows
   - 1-second hop
   - 128 mel bins
   - maximum 65 time steps
6. Run actual TensorFlow/Keras model.predict() on the processed audio.
7. Obtain V2 and V4 predictions separately.
8. Calculate a 50/50 ensemble score from V2 and V4.
9. Display the result clearly.

MODEL INFERENCE
- Load the models once when the Flask application starts.
- Use model.predict() for inference.
- Never fabricate predictions.
- Never use the filename to influence the prediction.
- Never use MD5/random values to generate a prediction.
- Never silently fall back to heuristics.
- If inference fails, show a clear error instead of inventing a result.
- Handle Keras/TensorFlow compatibility carefully.

RESULT PAGE
After upload, show:
- Audio filename
- Audio duration
- Speech/audio validation status
- V2 prediction
- V4 prediction
- 50/50 ensemble score
- Final risk level: LOW / MEDIUM / HIGH
- Processing time
- A clear statement: “Prediction generated by trained V2 + V4 TensorFlow/Keras models.”

Use a sensible risk mapping based on the ensemble score, but clearly label it as the application's risk classification rather than model accuracy.

UI
Create a professional cybersecurity-style dashboard suitable for an SIH 2026 demonstration:
- Dark modern interface
- VoiceShield AI branding
- Large audio upload area
- Analyze button
- Loading/progress state while inference runs
- Clean result card
- Risk indicator
- V2/V4/ensemble values
- Processing time
- Error messages
- Responsive layout

API
Create:
GET /health
POST /predict

/health must report:
- application status
- TensorFlow/Keras availability
- V2 model loaded status
- V4 model loaded status

/predict must accept the uploaded audio and return JSON containing the inference results.

IMPORTANT DEVELOPMENT RULES
- Do not add unnecessary features such as blockchain, authentication, databases, payment integration, telecom integration, speaker recognition, or audit systems yet.
- Do not generate fake demo audio.
- Do not claim any accuracy percentage unless it is actually measured from an evaluation dataset.
- Do not claim real-time call detection yet. This MVP analyzes uploaded recordings.
- Keep the code modular so these features can be added later.
- Install all required dependencies.
- Run the application and verify that both trained models load successfully.
- Test the /health endpoint.
- Test the /predict endpoint with an uploaded audio file if one is available.
- If there is a technical issue, fix the implementation rather than replacing the ML inference with a workaround.

FINAL REQUIREMENT:
Before considering the task complete, explicitly verify that V2 and V4 are loaded from the .keras files and that predictions are produced through TensorFlow/Keras model.predict().
